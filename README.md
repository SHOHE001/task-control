# task-control — 今の一手

案内を受け取る → 期限の根拠を確かめる → 一手を始める → 中断した地点へ戻る → 提出を本人が確認する、という流れを支える単一ユーザー向けWebアプリです。スマホ優先の日本語UIです。医療・診断機能、学習時間の推測、大学サイトの自動取得はありません。

## ローカル起動

Node.js **22.18以上の22.x** とnpmを使用します。SQLiteはNode組み込みAPI（22.xではexperimental）を使います。Redisなどの別サービスは不要です。

```sh
npm ci
cp .env.example .env
npm run setup
npm run build
npm start
```

`setup` は端末で初回パスワードを非表示入力します（12文字以上、固定パスワードなし）。設定済みDBへ上書きしません。別の端末で `npm run worker` を起動し、[ローカル画面](http://localhost:3000) を開きます。APP_ORIGINとアクセスURLは一致させてください。外部連携キーがなくてもコア機能は動作します。パスワードだけは初回設定が必要です。

開発用HMRを使う場合はAPP_ORIGINを `http://localhost:5173` にし、`npm run dev` と `npm run dev:ui` を同時に起動します。運用時はビルド済み画面を単一のアプリプロセスが配信します。

## 使い方

- **登録・受信箱**：タイトルだけ、または案内文の貼り付けで保存。リンク以外の追加入力は要求しません。
- **期限の確認**：原文を見て、年月日・時刻・タイムゾーンのうち分かった範囲を明示的に確認。「9月18日」から年や23:59を補完しません。「明日」は発信日時が不明なら未確認です。
- **今の一手**：選定理由と今回の終了条件を持つ主カード1件。期限が近いものや未確認事項は別の小さな領域に残します。一覧から自分で別の作業を選べます。
- **開始・中断・再開**：開始時は作業リンクへ移動。中断メモは候補のままでも保存できます。ページを開いたことから作業量や集中を推測しません。
- **終了**：「一手の終了」「作業全体の終了」「提出の本人確認」は別操作。提出完了画面などを自分で確認してから記録します。誤操作は再開操作で修正できます。
- **週の照合**：自分で大学の一覧と登録済み課題を比較し、実施を記録します。大学サイトをシステムが確認したことにはしません。

## 設計判断

TypeScript / Fastify / React / Vite / SQLite。Webと単一の軽量workerが同じローカルDBを使います。SQLiteのWALとトランザクションで状態変更・履歴をまとめて保存し、APIのリビジョン検査で別画面の上書きを拒否します。DBスキーマは `migrations/001.sql`。`npm run migrate` または起動時に適用します。

期限は種類（不明・明示的になし・日付・日時）と本人確認の有無を分けます。日付は暦日文字列、日時は日付・時刻・確認したタイムゾーンとして保持します。抽出候補は未確認のまま。原文引用または本人の確認内容、変更前後、確認日時が履歴に残ります。着手予定は独立フィールドで、専用API以外から期限を変更できません。

ホームの順位は「24時間以内の確認済み日時／当日の確認済み日付 → 着手予定を迎えたもの → 本人指定の重要 → 期限経過 → 未確認 → 中断中 → その他」。同順位は登録順です。見積時間の不明はnullです。時間・端末による絞り込みは初版では設けません。本人が選んだ作業を優先し、中断・一手終了後は30分ホーム候補から外して次へ移れるようにします（重要期限の注意表示と一覧からの選択は維持）。未操作から怠慢などを推測しません。

通知はDB上の予定・配信履歴・端末ごとの受理を保持します。workerのリースで二重起動を抑制し、送信ジョブにもリースと一意キーを付けます。古い通知は取消、1時間以上遅れた通知は省略。送信は最大3ジョブ/分、失敗再試行は最大3回。既に受理された端末への再送を避け、同一通知tagで端末上の重複も抑えます。ただし、外部受理直後のクラッシュ等をまたぐ完全な一度限りの到達は保証しません。送信中に期限を変更した場合、既に外部へ出た要求は取り消せません。

カレンダーは本人確認済み期限のみを専用カレンダーへ一方向同期。タスクから決まる予定IDと所有マーカーを保存・検査し、管理外の予定には触れません。日付のみは終日・時刻未確認表記で、Googleの既定リマインダーを無効にします。日時の予定長1分はカレンダー表示上の容器で、作業時間の見積もりではありません。失敗は最大5回の間隔付き再試行、その後は設定画面から手動再試行。変更失敗時は外部に古い期限が残る可能性を表示します。

AIは任意のHTTPS OpenAI互換chat/completions接続先を設定できます。設定画面で送信内容に同意し、候補ボタンを押したときだけ原文等を送信します。原文とAI出力を命令として実行せず、出力構造と引用を検査します。期限・状態変更の権限はありません。未設定・停止時の候補は明示的に「テンプレート」と表示します。ローカルの期限候補抽出は保守的な規則で、網羅的な自然言語解析は行いません。

## 検証

```sh
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm audit --omit=dev --audit-level=high
```

自動テストは架空データ専用のインメモリDBまたは一時DBを使用し、実際の通知・Google・AIへ送信しません。本番へサンプルを投入する機能はありません。受入条件の対応は [テスト・実機チェック](docs/testing.md) を参照してください。

## 運用・既知の制限

[配置・HTTPS・バックアップ・復元](docs/operations.md) / [Push・Google・AI設定](docs/integrations.md) / [開発運用](docs/development-workflow.md)

Gen8のOS・ドメイン・既存認証・ネットワーク公開方式は未確定として扱います。本リポジトリには汎用のLinux/systemd配置例を同梱しますが、本番へ自動反映しません。接続情報や実データは公開リポジトリへ保存しないでください。

PWAはホーム画面追加とPushを提供します。オフライン編集はありません。Service Workerは個人データも画面もキャッシュせず、保存失敗は成功と表示しません。初回ロードも通信が必要です。通信断時の入力は画面を閉じる前に手元へ控えてください。

Googleの実認可・実同期、実Push到達、外部AIの実呼出し、iPhone実機、Gen8への配置は、資格情報や実機を使用していない段階では未接続・未検証です。アプリのソース公開とWebアプリの本番公開は別です。カレンダー同期先の変更・アカウント切替は初版のUI対象外で、移行前に所有予定とトークンを管理者が整理する必要があります。
