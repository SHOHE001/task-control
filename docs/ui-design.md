# 日常の操作を中心にしたUI

「今日・課題・追加・設定」の4つに役割を分ける。今日の画面では取り組む課題1件と主操作を大きく示し、締切の注意は補助領域に置く。PCはサイドバー、狭い画面は下部ナビゲーションとする。

課題の状態に合わせて着手、中断、作業終了、提出確認を順に表示する。編集や原文、履歴、外部連携は必要なときに開く。締切の根拠という内部的な言葉を日常の主操作に出さず、「締切はいつ？」で既存候補を本人が明示的に保存する。候補の自動確定や未知の年・時刻・地域の補完は行わない。予定変更と締切変更は引き続き別APIを使う。

既存の自動生成された確認手順だけを表示時に平易な作業案内へ置き換える。本人が書いた作業やメモはそのまま表示し、既存データの書換え・移行はしない。作業完了と提出確認の区別を保ち、提出には本人確認のチェックを必要とする。

Apple HIGの明瞭な情報階層と、[短く任意で、操作の近くに置くオンボーディング](https://developer.apple.com/design/human-interface-guidelines/onboarding)を参考にした。システムフォント、青い主操作、控えめな面と余白を使う。ダークモード、44px以上の操作領域、remの文字サイズ、フォーカス表示、動きを抑える設定に対応する。フォームは標準dialogを使い、Escapeと閉じた後のフォーカス復帰を提供する。

3画面の使い方はスキップ可能で常に再表示できる。完了状態はブラウザーのlocalStorageにのみ保存し、見本は表示専用で課題を作成しない。チュートリアルを読まなくても操作できる文言と構造を優先する。
