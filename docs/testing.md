# 自動テストと実機チェック

2026-09-08：ローカルでサーバー側34件・ブラウザー8件、lint/typecheck/buildが成功。初回GitHub CIも成功。実サービス・iPhone実機・Gen8配置は未検証。

## 自動検証の対応

`tests/core.test.ts` に要件の番号を付けています。

| 要件  | 検証内容                                                                  |
| ----- | ------------------------------------------------------------------------- |
| 1–3   | タイトルのみ、日付のみ、相対日付・年不明を保守的に保存                    |
| 4     | 着手予定変更後も期限・履歴を保持、通常編集APIから期限を書けない           |
| 5     | AI未設定と障害時のテンプレート、期限不変                                  |
| 6     | 1件の主候補、理由、注意領域、本人選択、延期の尊重                         |
| 7–8   | 開始/一手終了/作業終了/本人提出確認の分離と修正、再開メモ・リンク保存     |
| 9     | ファイルDBを閉じて再オープン後に状態・通知予定を保持                      |
| 10–11 | 古い通知取消、期限切れ省略、送信上限、受理済み端末のスキップ、最大再試行  |
| 12–13 | fake Calendarへの冪等同期・管理予定削除、古い外部期限の可能性の表示       |
| 14–15 | 未認証・異なるOrigin・危険URL・古いリビジョンを拒否、DB失敗のロールバック |
| 16    | WAL中の変更もonline backupし、別DBでintegrity_checkとデータ確認           |

ブラウザーテストは架空データで次の8ケースを確認します。

1. スマホ幅で追加→締切入力→着手→中断→再読込→再開→作業終了→本人提出確認。
2. タイトルのみ・締切不明でも着手でき、一手の終了を提出として扱わない。
3. 通信断時に登録入力を保持し、失敗を表示。
4. 3画面の使い方をスキップ・再表示でき、課題を作らない。
5. ダイアログのフォーカス保持、Escapeとフォーカス復帰、締切保存失敗時の入力保持。
6. 着手予定を変えても締切が変わらない。
7. PCのサイドバー、ダークモード、スマホ幅で文字を200%にした際の横はみ出し防止。

8. 自然文1欄だけで未確認期限・着手予定・小さい行動が保存され、登録直後に詳細入力を要求せず、予定を取り消しても期限を変えない。

`tests/intake.test.ts` では指定例文、希望優先、元情報の基準日時不明、年/時刻の不確実性、認証/Origin、原子的履歴、Start/Deadlineの独立同期、所有マーカー、409競合、最大再試行、同期中のrevision変更、取消/reopen、旧DB移行とbackup、Pushの課題名非表示をfake providerで確認する。

Chromiumによる検証です。iPhone実機やスクリーンリーダー実機での確認は含みません。テストは同じ認証済みセッションを再利用し、本番のログイン回数制限を変更しません。

## 本番利用前の手動チェック

- [ ] Gen8のOS、保存先、Nodeのバージョン、ドメイン・公開範囲を確認した。
- [ ] HTTPSでログインでき、未ログイン端末で個人データAPIを読めない。
- [ ] 自分のiPhoneでホーム画面へ追加でき、主要導線と作業リンクが動く。
- [ ] 通知許可の未許可/拒否/許可を確認し、本人がテスト通知を予約した。
- [ ] アプリを閉じた端末へ届くことを実機で確認し、DBの受理とは区別した。
- [ ] worker停止・復帰時に過去の通知が大量に届かず、省略/取消履歴を確認した。
- [ ] Google認可と明示的な専用カレンダー設定を行い、日付のみが終日で表示される。
- [ ] 許可した実データで期限更新と再同期を確認し、予定が増えず、管理外の予定が変わらない。
- [ ] バックアップを別の検証用DBへ復元し、外部配信を止めた状態で内容を確認した。
- [ ] 数日後の再開で、保存したメモと作業リンクから戻れる。

実機・実資格情報を使う検証は未実施ならチェックしません。公開Issueへ実データや認可コードを貼らないでください。試行の評価は登録した課題の期限経過と本人確認した提出、登録・再開の手間で判断し、未操作時間から学習時間を推定しません。
